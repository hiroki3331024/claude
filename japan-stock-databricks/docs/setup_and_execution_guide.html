Japan Stock Databricks Pipeline

J-Quants API から日本株データを取得し、Databricks Free Edition 上で Bronze → Silver → Gold の Medallion Architecture を構築する手順書です。

Databricks Free Edition J-Quants 無料プラン Delta Lake Unity Catalog

🗺 概要・アーキテクチャ

このパイプラインは日本株の OHLCV データを J-Quants API から定期取得し、 Databricks の Medallion Architecture (Bronze / Silver / Gold) で管理します。 Gold テーブルには移動平均・リターン・ボラティリティ等のテクニカル指標を付与し、 SQL Dashboard と Genie (AI によるデータ探索) で可視化します。

✅ 前提条件

確認事項
作業開始前に以下がすべて揃っていることを確認してください。
  • J-Quants アカウント (無料登録、メール認証済み)
  • Databricks Free Edition アカウント (databricks.com/try-databricks)
  • GitHub アカウントとこのリポジトリへのアクセス権
  • Python 3.9 以上 (ローカルテスト用、任意)
制限事項
J-Quants Free プランでは直近3年分の株価データのみ取得できます。 Databricks Free Edition はコンピュートリソースに制限があるため、 初回ロードは数十分〜1時間程度かかる場合があります。

🔒 Databricks Secrets の登録

認証情報は Databricks CLI を使って Secret Scope に登録します。 クラスターやノートブックから dbutils.secrets.get() で安全に取得できます。

Databricks CLI のインストール

shell 
pip install databricks-cli

# Workspace URL と Token で認証
databricks configure --token
# Host: https://<your-workspace>.azuredatabricks.net
# Token: (Databricks UI の User Settings > Access Tokens で生成)

Secret Scope と Secret の作成

shell 
# Scope 作成 (初回のみ)
databricks secrets create-scope --scope jquants

# J-Quants 認証情報を登録
databricks secrets put --scope jquants --key email
# → プロンプトに メールアドレス を入力

databricks secrets put --scope jquants --key password
# → プロンプトに パスワード を入力

# 確認
databricks secrets list --scope jquants
登録後の確認
ノートブックのセルで dbutils.secrets.get(scope="jquants", key="email") を実行し、 [REDACTED] と表示されれば正常です（値は直接表示されません）。

テーブル説明例 (stock_with_master) 
日本株の日次株価データにテクニカル指標と銘柄マスタを結合したゴールドテーブルです。
- trade_date: 取引日 (日付型)
- code: 銘柄コード (例: 7203 = トヨタ)
- company_name: 銘柄名 (日本語)
- sector17_name: 17業種区分 (例: 自動車・輸送機)
- close: 権利修正済み終値 (円)
- return_1d: 1日リターン (%)
- return_5d: 5営業日リターン (%)
- ma5, ma25, ma75: 5日・25日・75日移動平均
- volatility_20d: 20日ボラティリティ (標準偏差)
- turnover_value: 売買代金 (円)

🛠 トラブルシューティング

J-Quants 認証エラー (401 Unauthorized)

原因と対処

原因: Secret の登録内容が誤っているか、J-Quants のパスワードが変更された。

対処: databricks secrets put --scope jquants --key password で再登録してください。

Bronze テーブルが作成されない

確認コマンド 
# ノートブックのセルで実行
spark.sql("SHOW SCHEMAS IN main").show()
spark.sql("SHOW TABLES IN main.bronze_stocks").show()

スキーマがない場合は sql/create_schemas.sql を SQL Editor で実行して スキーマを作成してください。

Gold テーブルの指標が全て null

Silver テーブルのレコード数が不足しています。移動平均には最低 MA のウィンドウ日数 (例: MA75 なら 75 日以上) のデータが必要です。 初回ロードが完全に完了しているか確認してください。

DQ チェックが FAIL する

sql 
-- 失敗した銘柄・日付の特定
SELECT trade_date, code, close, volume
FROM main.silver_stocks.daily_quotes
WHERE close IS NULL OR close <= 0
ORDER BY trade_date DESC
LIMIT 20;

J-Quants 側でデータ未配信の銘柄や休場日が混入している場合があります。 少数であれば正常範囲です。data_quality.py の fail_on_error=False に変更してパイプラインを継続させることもできます。

Out of Memory エラー

Free Edition のリソース制限
Gold テーブルの Window 関数計算はメモリを大量消費します。 初回ロード時に OOM が発生した場合は、Gold 構築を日付範囲を区切って 段階的に実行してください。
python (ノートブックで実行) 
# Spark の設定でシャッフルパーティションを削減
spark.conf.set("spark.sql.shuffle.partitions", "8")
